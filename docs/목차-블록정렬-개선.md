# 목차·블록 정렬과 페이지 추가 버튼

2026-10-30 사용자 요청으로 ICT 최종 PDF 5·14페이지와 삼성전자 참고 장표 8페이지의 로컬 렌더링, 기존 컨설팅·마케팅 분석 및 Claude 스킬셋 적용 기준을 재검토했다. 원본 내용·로고·색상은 새 덱으로 복사하지 않았다.

## 적용

- 페이지 추가는 세 가지 시안 중 사용자가 고른 A: 얇은 구분선 사이 작은 ‘＋ 페이지 추가’ 버튼이다. 초록색 채움 막대를 없애고 흰 배경·초록 테두리를 쓴다. 보조기기용 이름은 ‘N번과 N+1번 사이’로 위치를 유지한다.
- 컨설팅 상단: 덱 이름은 좌측 작은 보조 글씨, 섹션 그룹은 우측의 최대 6개 균등 탭, 현재 섹션만 주색 강조, 선은 0.65pt로 줄였다. 긴 덱 이름이 탭을 침범하지 않도록 줄인다. 6개를 넘는 경우 현재 섹션을 포함한 구간을 보여준다. 표지·독립 목차·마케팅 콘셉트 장에 상단 탐색을 억지로 추가하지 않는다.
- 통찰+근거의 우측 블록 전체 높이·하단선을 좌측 통찰 블록에 맞춘다.
- 전후 비교의 모든 열 간격을 0.2in로 통일하고, 본문 행은 전체 높이를 같은 간격으로 나눈다.
- 원인 트리의 하위 원인 묶음과 부모 블록의 위·아래선, 연결선 중심을 맞춘다.
- 마케팅 카드의 열 너비와 간격, 이미지/카피의 양쪽 여백을 균등하게 정리한다.
- 추세 차트의 막대 그룹을 가로축 안에서 중앙 배치해 좌우 여백을 맞춘다. 퍼널의 좁아지는 폭과 통찰·근거의 의도적인 좌우 비율은 유지한다.

공통 장면(makeScene) 수정으로 기존 저장 후보의 미리보기와 네이티브 PPTX에 같이 반영한다. 데이터·후보·직접 수정 기록을 초기화하지 않는다. 작은 좌표 조정으로 원본 요소 키가 달라진 경우 동일 내용과 인접 위치의 편집값을 연결해 유지한다. 사용자가 직접 바꾼 위치·크기는 자동 정렬로 덮지 않는다.

## 확인 자료

63개 테스트와 TypeScript 검사 통과. 수정된 정렬, 6개를 넘는 목차의 현재 섹션, 직접 수정 보존을 검사한다. 35개 레이아웃을 로컬 SVG/PNG로 그려 축소 모음과 대표 개별 이미지를 확인했다. 실제 사용자 입력의 모든 길이 조합이나 유료 AI 생성 품질까지 확인한 것은 아니다.

최종 프로덕션 빌드 통과. 데모 브라우저에서 기존 7장 유지, 수정된 목차·통찰 블록, A안 버튼의 입력 폼 열기·닫기를 확인했다. 실제 적용 화면은 `web/output/screenshots/header-spacing-and-insert-A.png`다.

- 시안: `web/output/screenshots/page-insert-options.png`
- 35개 모음: `web/output/screenshots/layout-alignment-contact-sheet.png`
- 개별 화면: 같은 폴더의 `alignment-*.png`
- 네이티브 검토 덱: `web/output/layout-alignment-review.pptx` (구성 예시, 실제 분석 아님)
- 검토 HTML: `web/output/layout-alignment-review.html`, 버튼 비교 `page-insert-options.html`

브라우저의 file URL 정책으로 검토 HTML을 직접 여는 작업은 허용되지 않았다. 해당 파일을 다른 URL로 우회해 열지 않았으며, 로컬 벡터 렌더링 이미지로 검토했다. 앱 화면은 정상 허용된 localhost 주소에서 따로 확인한다.
