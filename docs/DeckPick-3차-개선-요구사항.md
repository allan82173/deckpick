# DeckPick 3차 개선 · 실행 계약

사용자 요청일 2026-11-07. 이 문서는 요청을 보존한 것이며 구현 완료 보고가 아니다. 실제 단계별 결과는 `DeckPick-3차-안정화-진행.md`를 따른다.

## 공통 제약

- 목표는 안정적인 종료, 비용·시간 절감, 재현 가능한 측정이다. Luna·사용자 키·디자인 선택·후보·직접 편집·첨부·장별 대화·PPTX를 유지한다.
- 숫자 예산은 `web/src/lib/generation-config.ts`에 모은다. 특정 과제·업종·지역의 특례를 넣지 않는다.
- 삭제 전 확인한다. 유료 실행은 필요한 최소만 하며 예상 호출·토큰·시간을 먼저 보고한다. 실패를 성공으로 덮어쓰지 않고 실행마다 리포트를 남긴다.
- 각 단계 완료 기준을 통과해야 다음 단계로 진행한다. 미통과 시 원인·대안을 보고한다. 4단계 대규모 실험은 별도 승인 후 실행한다.

## 1 · 안정화

공개·첨부 근거를 행별 검증한다. URL·질문 ID·구조 오류만 rejectedRows에 사유와 함께 남기고 제외한다. 인용 대조 실패는 originalText를 비워 원문 미확인 행으로 보존한다. 유효 행이 0개일 때만 재시도하며, 계속 0개면 gaps로 넘기고 진행한다.

기본 전체 시간 제한: 조사 질문 4분, 스토리라인 4분, 장 후보 생성 3분, 덱 검토 4분. 연결·지연은 형식 재시도와 별도로 지수 백오프 최대 2회. 검토 시간 초과는 생성 장을 반환하고 검토 미완료로 표시한다.

과제 해석·조사 계획·근거표·판단·스토리라인·후보·검토를 단계별 저장한다. 마지막 완료 단계부터 재개하고 UI에 이어서 생성 버튼을 둔다.

문턱: 오류 행을 섞어도 종료, 강제 검토 시간 초과에서 장 반환·미완료 표시, 중단 후 재개 성공.

## 2 · 비용과 시간

목표: 한 번 10분 이내, 기존 C 입력 토큰의 1/3 이하. 후보·장별 대화는 해당 장 evidenceRefs만, 판단·스토리라인·전체 검토는 질문당 최대 8행을 전달한다. 맥락 일치→원문 확인→자료 유형→발행일 순위. 첨부 근거와 confirmedDecisions는 중복만 합쳐 전체 유지한다.

근거 추출에는 질문 핵심어 문단과 앞뒤 1문단만 전달하며 페이지 글자 한도를 설정한다. quoteExists는 축소 전 전체 원문으로 대조한다. 같은 URL 또는 같은 출처의 같은 주장을 합친다. 질문 조사·장 후보 생성 동시 작업은 기본 3개.

문턱: 시장 진입 1회 실측의 시간·호출·입력 토큰 기록, 목표 근접 여부 판정, 장별 전달 전후 근거 수 보고.

## 3 · 맥락 기준과 합성 과제

회사명·제품명이 아닌 publicContext의 지역·시장·기관·기간·대상으로 맥락을 판정한다. 지역과 시장 또는 대상이 맞으면 일치, 일부만 맞으면 부분 일치, 다르면 비교 참고. contextReason에는 일치·불일치 항목을 적고 지표에서 일치와 부분 일치를 따로 센다.

합성 5과제의 회사·제품만 가상으로 두고 지역·시장·기관·기간은 실제 공개 맥락을 쓴다. 사람이 사전 작성한 공개 확인 사실 예시 3개씩을 fixtures에 보관하고 발견 수를 기록한다.

문턱: 과제 5개와 사전 사실 15개, 기존 실행 1개의 새 기준 오프라인 판정 보고.

## 4 · 고정 조사 비교 실험과 사람 평가

검색 결과·전체 원문·근거표를 실행 ID로 캐시한다. researchCache는 new 또는 기존 실행 ID다. 같은 입력에서 같은 캐시를 쓰면 근거표가 동일해야 한다.

과제별 조사 캐시 1회, 같은 캐시로 A/B/C 각각 3회 실행한다. A는 전 단계 low, B는 판단·스토리라인·검토 medium 및 나머지 low, C는 전 단계 medium. 5과제 기준 조사 5회와 후속 실행 45회다. 총 호출·토큰·시간을 구체적으로 먼저 보고하고 승인받기 전 실행하지 않는다. 지표는 평균과 최소~최대를 함께 보고한다.

조건을 가린 run-07.pptx 같은 이름으로 결과를 내보낸다. 조건과 실행 ID의 대응표는 별도 보관한다. 빈 사람 평가 CSV는 근거·타깃·실행·장표·사실 구분 5개 항목을 각 1~5점으로 채우게 한다. 사람이 채우기 전 점수를 만들지 않는다. 평가 후에만 조건표를 합친다.

문턱: 동일 캐시 2회에서 근거표 동일, 검토 가능한 실험 계획·예산, 실행 승인.

## 5 · 렌더러 좌표 경고

기존 실행 전체 경고를 레이아웃·경고 종류별 집계하고 상위 3개를 수정한다. 글자량에 따른 박스 높이, 라벨 회피, 스키마 글자 상한을 우선 검토한다. 모델에게 문구를 고치게 해 좌표 경고를 없애지 않는다.

문턱: 같은 데이터의 수정 전후 이미지와 경고 감소, 다른 레이아웃 출력 보존. 모델 생성 품질의 향상으로 오해하지 않게 오프라인 렌더러 효과를 따로 보고한다.

## 6 · effort 확정

4단계 지표와 실제 사람 점수를 보고 단계별 기본값을 정한다. 근거 추출 low·medium 원문 대조 성공률을 따로 비교하고 차이가 없으면 low로 둔다. 실험이나 사람 평가가 없으면 확정하지 않는다.

문턱: 최종 설정과 실제 근거 문서. 미측정 결과나 소감을 만들지 않는다.
