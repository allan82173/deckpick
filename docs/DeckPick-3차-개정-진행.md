# DeckPick 3차 개선 · 개정 진행 기록

사용자 후속 지시(2026-11-07)가 기존 순차 진행 기준보다 우선한다. 과거 실패·재개 기록은 `DeckPick-3차-안정화-진행.md`에 그대로 보존하고, 이번 판정에는 합치지 않는다.

## 변경된 실행 계약

- market-entry 원래 입력을 처음부터 1회 실행한다. 단계 저장본·공유 첨부 캐시를 재사용하지 않는다. Luna·키·effort·디자인 선택은 유지한다.
- 외부 5xx·연결 오류로 종료된 경우에만 같은 입력·코드·설정으로 최대 1회 새로 실행할 수 있다. 형식·내부 시간 제한·품질 실패를 외부 오류로 바꿔 재실행하지 않는다.
- 전체 장 생성과 검토 완료, 15분 이내, 이전 C 대비 40% 이상 단축, 입력 1/3 이하를 각각 판정한다. 이전 C 실제 기록은 1,500,880ms·입력 1,898,015토큰이다.
- 미반환 입력은 요청 JSON 텍스트의 o200k_base 길이로 추정하고 이미지가 있으면 설정된 보수적 이미지 예산을 더한다. 원문·키·base64는 기록하지 않는다. 제공자 반환값과 추정치를 구분하고 ‘추정 포함’으로 판정한다. 도구 내부 문맥·실제 청구액과 다를 수 있다.
- 3·5단계는 2단계와 독립해 오프라인 진행한다. 4단계는 2단계 통과 후 계획·예산에 별도 승인 필요, 6단계는 실제 4단계 결과와 사람 평가 이후다.

## 현재 구조와 수정 계획

기존 과제 해석→질문별 공개 조사→판단·스토리라인→최대 3개 장 생성→전체 검토·최대 2회 내용 수정·리포트 구조를 유지한다. 행별 검증·520 포함 재시도·URL enum·단계 저장과 재개는 보존한다. 새 작업은 맥락 항목별 판정, 입력 추정치와 새 판정기, 실제 공개 맥락의 별도 평가 과제, 경고 상위 3유형의 렌더러 수정이다. 색·테마·사용자 키·모델을 바꾸지 않는다.

## 3단계 · 맥락 기준과 평가 자료

### 파일과 동작

- `web/src/lib/context-match.ts`: contextChecks의 dimension·value가 taskAnalysis.publicContext에 있는 항목인지 확인한다. 회사·제품명을 판정 기준으로 받지 않는다. 지역과 시장 또는 대상이 맞으면 일치, 일부만 맞으면 부분 일치, 다르면 비교 참고, 근거가 없으면 불명확이다. 지역 또는 초점이 지정되지 않은 과제는 지정된 축으로 판정한다. 기관·기간은 contextReason/checks에 보존하며 핵심 조합을 대신하지 않는다.
- `evidence-model.ts`, `research-questions.ts`, `evidence-selection.ts`: 부분 일치를 저장·추출·정렬에 연결한다. 근거표 추출 한 번 안에서 공개 맥락별 근거 범위를 평가하며 별도 모델 호출을 추가하지 않는다. 기존 저장 데이터도 읽을 수 있다. 새 검색 결과는 항목별 체크를 요구하며, 항목별 체크가 없는 구형 기록의 판정은 임의 변경하지 않는다.
- `run-report.ts`: 일치·부분 일치·원문 대조 수, 항목별 이유를 기록한다. 행 수와 서로 다른 주장·URL 수를 구분한다. 서로 다른 URL이 별개 조사·독립 연구라는 뜻은 아니다.
- `web/tests/fixtures/general-decks-v3.json`와 `.md`: 시장 진입·내부 업무·학술 요약·제품 피치·정책 5과제. 회사·제품만 가상, 실제 지역·기관·기간을 지정했다. 공식 원문을 확인한 사전 사실 3개씩 총 15개를 별도 평가 항목으로 두었다. 정답 사실 목록을 생성 입력에 넣지 않는다.
- `web/scripts/reclassify-context.ts`, `output/stability-stage3/`: 기존 C 시장 진입 1개를 같은 조합 기준으로 오프라인 판정했다. 원본 실행 JSON·인용·대조 상태는 바꾸지 않았다. 항목별 판정 주석도 별도 보관한다.

### 오프라인 결과

기존 C 기록 33개 공개 주장: 일치 0·비교 참고 33·원문 대조 29. 새 기준의 오프라인 판정: 일치 1·부분 일치 32·원문 대조 29. 서로 다른 URL 기준은 일치 1·부분 일치 6·원문 확인 URL 4다. 숫자가 증가한 것은 분류 기준의 변경이며 조사 성공이나 새 근거 확보가 아니다. 2020년 수도권 반려견 지출 자료는 지역·대상이 맞더라도 방문 돌봄 수요를 입증하지 않으며 기간 한계를 유지한다.

사전 사실과 오프라인 판정은 **AI가 원문·기존 기록을 읽고 작성**했다. 사람이 작성·확정했다고 표시하지 않았다. 사람 검토는 미완료다. 새 합성 5개 과제를 유료 생성하지 않았으므로 발견 수를 0으로 만들지 않고 미측정으로 남겼다.

## 5단계 · 렌더러

기존 실행 기록의 저장된 83장에 동일 검사기를 적용해 상위 3개 유형을 골랐다. 주장·근거 복합 구성 32→4건, 지표+패널 16→0건, 비교표 13→0건으로 경고가 줄었다. 대상 외 63개 장면의 nodes·warnings는 동일했다. 이전 49개 기본 예시의 장면·PPTX XML 회귀 검사도 통과했다.

파일: `web/src/lib/adaptive-scene.ts`, `scene.ts`, `generation-config.ts`, `scripts/renderer-stability-baseline.ts`, `renderer-stability-after.ts`. 원문과 수치를 줄이지 않고 텍스트 길이에 따른 헤더·행·결론 바 높이와 지표 배치를 조정한다. 새 좌표는 미리보기와 편집 가능한 PPTX에 공통 적용한다. 넘어가지 않는 기존 장면은 유지한다. 수동 편집 호환성도 별도로 검사한다.

전후 PNG·경고 종류 집계·보고서는 `web/output/stability-stage5/`에 있다. 비교 이미지는 직접 열어 확인했다. 남은 4건은 기존 경로의 작은 글자 경고이며 모든 레이아웃의 문제가 해결됐다고 보고하지 않는다. 실제 PowerPoint 앱에서 새로 열어 확인한 것은 아니다.

## 2단계 · 깨끗한 실측

`web/scripts/benchmark-clean.ts`가 새 실행 ID·빈 단계 저장소·첨부 캐시 우회로 시작한다. 코드·설정·입력·모델 해시를 기록해 반복 조건을 비교하고, 성공·실패별 별도 MD/JSON 리포트를 남긴다. 실패 기록은 덮어쓰지 않는다. 기존 제한 근거 진행 평가 정책을 유지하며 gaps를 숨기지 않는다.

사전 보고: 40~65호출, 입력 35만~65만 토큰, 10~15분(재시도 초과 가능). 최초 실행 결과는 아래에 기록했다. 이전 실패·재개 실행은 판정에 합치지 않았다.

입력 추정 관련 파일: `usage-estimate.ts`, `execution-model.ts`, `ai.ts`, `run-report.ts`. 판정은 `benchmark-gates.ts`와 중앙 설정을 사용한다. 최종 자동 테스트 147개·타입 검사·빌드가 통과했다. 새 자동 배치의 편집 저장 호환성 2개 테스트를 포함한다.

## 4·6단계

4단계 대규모 유료 비교는 아직 실행하지 않았다. 2단계 판정 후 진입 여부를 정하고, 실행 전 총 호출·토큰·시간을 보고해 승인을 받는다. 6단계 effort는 실험과 사람 평가 없이 확정하지 않는다. 현재 medium/low 설정은 기존값 유지다.

## 실행 후 오프라인 보완과 한계

1. **편집 호환성:** 새 자동 배치 장표를 처음 직접 편집할 때 rendererVersion=adaptive-v3를 저장한다. 이후 저장·다시 읽기에도 같은 배치를 사용한다. 기존 수동 편집 데이터에는 이 표시를 자동으로 붙이지 않아 기존 좌표를 보존한다. `model.ts`, `canvas-edits.ts`, `adaptive-scene.ts`, `tests/adaptive-edit-compat.test.ts`를 수정했다. 실패를 재현한 테스트와 수정 후 통과 기록을 stage5 폴더에 따로 남겼다.
2. **계산 오류 진단:** `scenario-calculation.ts`가 문제 단계·미정의 변수·사용 가능한 이름을 구체적으로 알린다. `storyline.ts`는 장 번호를 붙이고 operands가 assumptions.name 또는 앞 단계 steps.name만 참조해야 한다는 계약을 분명히 한다. 정의되지 않은 이름을 임의 연결하거나 값을 0으로 채우지 않는다. 기존 정상 계산 값은 바꾸지 않았다. 자동 검사로 진단을 확인했지만 이 보완으로 실제 생성 실패가 해결됐다고 주장하지 않는다.
3. 이 보완은 깨끗한 실행이 종료된 뒤 적용했다. 측정 조건 해시는 실행 당시 코드를 보존하며 **보완 후 유료 재검증은 하지 않았다**. 520 재시도·URL enum·같은 Luna·같은 예산은 유지한다. 향후에는 계산 한 부분의 실패가 큰 스토리라인 전체 수정으로 이어지는 경로를 줄이는 방안을 검토할 필요가 있다. 이번에 새 유료 경로나 추정 계산값을 넣지 않았다.

## 단계 판정과 남은 일

- 2단계: 깨끗한 1회 측정 완료, 전체 생성 조건 미통과. 외부 오류가 아니므로 허용된 재실행 조건에 해당하지 않는다.
- 3단계: 부분 일치 판정·합성 5과제·사전 사실 15개·기존 실행 1개 오프라인 판정을 준비했다. AI 작성·사람 미검토를 명시했다. 새 5과제 유료 생성 점수는 미측정이다.
- 5단계: 기존 83장 오프라인 집계·상위 3유형 수정·전후 PNG 확인·다른 63장 보존·새/기존 편집 호환 회귀 검사를 완료했다. 작은 글자 경고 4건은 남아 있다.
- 4단계: 2단계 미통과로 시작하지 않았다. 대규모 유료 실험 승인 요청·실행 모두 하지 않았다.
- 6단계: 실제 4단계 결과와 사람 점수가 없어 미진행. effort 기본값은 확정한 것이 아니라 기존 설정 유지다.
