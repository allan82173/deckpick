# DeckPick 실행 조건과 생성 리포트 — 2026-11-07

## 범위

모델·키·디자인 선택과 기존 편집·첨부·장별 대화·PPTX 기능을 유지하고 실행 조건을 개선했다. 특정 과제나 업종에 대한 특례는 추가하지 않았다. Vercel 공개 데모 설정은 변경하지 않았다. 삭제한 파일은 없다.

## 시작 시점의 구조와 변경 계획

`ai.ts`는 제공자 호출과 구조 검증을 공용으로 처리했지만 대부분 low/10,000을 공유했다. `task-analysis.ts`·`storyline.ts`·`deck-review.ts`는 각각 해석·현재 판단/주장 지도·전체 검토를 담당했다. `research-pipeline.ts`는 묶음 검색과 제한된 후속 검색을 수행했고 `source-pages.ts`에는 이미 PDF 추출이 있었다. 첨부 발췌만으로는 세부 조건이 단계 사이에서 누락될 수 있었다. `candidate-plan.ts`는 세 후보의 계열 차이를 강제했고 `slide-quality.ts`는 내용 채움·장면 경고를 검사했지만 이미지 검수는 없었다. `scene.ts`와 `export.ts`의 공통 장면·편집 가능한 PPTX 구조는 유지하기로 했다.

이에 설정 중앙화 → 전체 첨부 근거표·질문별 조사 → 선호 형식 우선 후보 배정 → 좌표/PNG 검수 → 실행 기록과 리포트 → 실제 Luna 비교 순서로 수정했다.

## 새 설정값

실제 설정의 기준은 `web/src/lib/generation-config.ts`다.

- 과제 해석/현재 판단/주장 지도/전체 검토: medium, 최대 출력 24,000.
- 조사 계획/검색/근거 추출/첨부 근거표/후보/이미지 검수: medium, 최대 출력 16,000.
- 형식 재시도/제목 교정/장별 대화: low, 최대 출력 10,000. 키 확인은 32(기존 Luna 호출의 none effort 유지).
- 출력 잘림: 10,000→16,000→24,000→32,000 사다리에서 다음 값으로 1회만 재시도. 일반 형식 검증은 최대 3회.
- 질문별 검색 최대 3라운드, 질문별 원문 최대 3시도, 덱 전체 12시도. 맥락 일치·원문 대조 근거 2개 시 종료. 실패 원문도 예산에 포함하고 다음 URL을 시도한다.
- 원문 최대 8MB/60,000자, 타임아웃 20초. PDF 추출 지원을 유지한다.
- 첨부 청크 12,000자, 청크당 최대 80항목, 이미지 4장씩 추출. 구조화 근거표 자체는 자르지 않는다.
- 품질 수정은 장별 최대 2회. 이미지 검수는 기본 켜짐이며 설정으로 끌 수 있다.

높은 출력 상한은 항상 그 토큰을 소비한다는 뜻이 아니다. 실제 제공자 반환 사용량은 각 생성 리포트에 기록한다. 단계별 low/medium/high를 설정에서 바꿀 수 있지만 모델은 교체하지 않는다. reasoning 미지원 모델에는 지원하지 않는 reasoning 옵션을 보내지 않는다.

## 리포트 저장과 개인정보

로컬 저장 위치는 `web/output/run-reports/{한국날짜}_{주제 앞부분}_{덱 해시}.md`와 `.json`이다. 같은 덱은 두 파일을 갱신하고, 같은 제목의 다른 덱은 해시로 구분한다. 전체 초안과 내려받기 화면에 버튼이 있다. 브라우저의 다중 다운로드 차단을 피하도록 Markdown/JSON을 각각 선택한다.

실제 설정 스냅샷, 제공자가 반환한 토큰, 조사 검색어·원문 URL·성공/실패/PDF, 과제 해석, 전체 근거표, 판단·반전 조건, 선택 장표·경고·재생성 횟수·시각 검수, 전체 검토를 담는다. 비공개 조건은 개수만 노출하고 확인된 값은 근거·판단 등에서도 마스킹한다. API 키·인증 필드와 첨부·채팅 전문은 직렬화 대상에서 제외한다. 원문 대조용 전체 텍스트도 리포트에 넣지 않는다.

예전 덱은 당시 실행 기록이 없으므로 모델·시간·토큰을 추정해서 채우지 않는다. 저장 데이터에 사용량이 없으면 null/누락으로 표시한다. 신규 생성부터 실제 단계 기록이 누적된다. 대기 시간을 포함한 전체 경과 시간과 실제 API 호출 소요 시간을 구분한다. 공개 소개 전용 모드에서는 기존 API 차단을 유지하므로 서버 자동 저장을 실행하지 않는다.

## 실제 비교에서 먼저 확인한 점

시장 진입 과제에서 A/B/C의 원문 대조 근거는 각각 8/8, 2/7, 29/33이었다. 그러나 C도 수도권의 방문 돌봄 서비스 수요를 직접 설명하는 맥락 일치 근거는 0개였다. 전국 양육 통계를 지역 서비스 수요의 확정 근거로 확대하지 않고 비교 참고로 남긴 결과다. C의 전체 검토에는 채널 후보의 과도한 묶음과 전환율 분모·측정 조건 불일치가 남았다. 따라서 조사량 증가는 확인했지만 핵심 판단의 검증까지 해결됐다고 볼 수 없다.

같은 과제에서 A 약 7.4분/40회, B 8.8분/29회, C 25.0분/79회였다. C는 추가 자료 추출·질문별 조사·이미지 판정과 재시도가 포함된다. 설정 상한 자체보다 실제 호출·반환 토큰·미해결 경고를 함께 보고 예산을 조절해야 한다. C의 레이아웃은 근거 범위 표·평가 매트릭스·비교표·가로 막대 계산·검증 계획 등으로 나뉘었지만 일부 작은 글씨와 시각 경고는 남았다.

학술 과제는 A/B에서 원문 인용 대조, C에서는 공개 검색 근거 형식 검증에 실패했다. C 제품 피치에서도 같은 계약 불일치가 확인됐다. 공개 조사 전용 출력 스키마를 일반 근거 유형에서 `공개 사실` 한 종류로 좁히고, 실제 검색 URL과 현재 질문 ID를 제공자의 네이티브 스키마에서 제한했다. 검증을 느슨하게 하거나 실패를 임의 근거로 대체한 수정이 아니다. 초기 실패 JSON은 보존하고 각 과제의 `.retry.json` 한 건을 추가로 기록한다. 이후 재실패에 대한 추가 유료 반복은 하지 않는다.

리포트 추가 검증에서 공개 URL의 숫자가 비공개 조건 숫자와 우연히 겹쳐도 링크를 훼손하지 않게 했고, 늦게 도착한 실행 기록이 종료 시각을 과거로 되돌리지 않도록 보완했다. 실제 호출의 effort와 이미지 검수 결과를 보존한다. 실패·재시도를 포함한 최종 결과는 comparison.md를 기준으로 갱신한다.

## 인용 실패 처리의 마지막 보완(v2)

학술 재실행은 공개 사실·URL·질문 ID 계약을 통과했지만 이후 연속 원문 인용 검사에서 다시 실패했다. 추가 유료 반복 대신 원문 대조 실패 행을 **근거표에서 제외**하는 처리를 추가했다. 원래 `quoteExists` 조건은 그대로 사용하며, 잘못된 인용이나 주장을 사실로 통과시키지 않는다. 제외한 URL·질문·사유는 `evidenceWarnings`와 화면 안내·생성 리포트에 남긴다. 나머지 유효 행은 보존한다. 유효 근거가 부족하면 `requiresReview=true`, `acceptedLimits=false`로 기존 사용자 확인 단계가 유지된다.

잘못된 행과 정상 행이 섞인 경우 정상 4행만 남기는 테스트, 모든 인용이 잘못된 경우 근거 0개·사용자 확인 상태가 유지되는 테스트가 통과했다. v2는 생성 설정의 version에 명시했다. A/B/C 표는 실측 당시 v1(및 공개 조사 계약 보완 후 1회 재실행)의 결과이며, 이 마지막 v2에 대한 전체 유료 재실행은 하지 않았다. 따라서 표의 실패를 v2에서 실제 성공한 것으로 바꾸지 않는다.
