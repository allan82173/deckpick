# DeckPick 4차 · 결과물 개선 계획 (교보문고 비교 기반) · 2026-11-08

작성: Claude. 상태: **계획만 있고 코드 변경 없음**. Codex의 사이트 수정이 끝난 뒤 Claude가 실행한다(동시 작업 금지).

## 1. 비교 결과 요약

같은 과제(교보문고 20대 대학생 공략 사업)로 DeckPick 초안(10장)과 Claude가 직접 만든 초안(12장)을 비교했다.

| 항목 | DeckPick 초안 | Claude 초안 |
|---|---|---|
| 결론 위치 | 9장에 가서야 나옴 | 2장 요약에서 1·2·3순위 바로 제시 |
| 핵심 메시지 톤 | 대부분 "판단할 수 없다 / 확인되지 않았다" | 단정형, 근거 강도는 [공개]·[추론]·[가설]로 표시 |
| 근거 최신성 | 2023 대학생 통계 위주 | 2025 독서실태, 텍스트힙·굿즈, 교보 강연 매진율, 바로드림 비중, 음반 감소 |
| 첨부 내부 자료 | 거의 안 씀 | n을 밝히고 '내부 전제'로 사용 |
| 레이아웃 | 라벨 박스형 반복, 작은 글자 | 큰 숫자·차트·2×2·단계 블록·타임라인 혼합 |
| DeckPick이 잘한 점 | 고객 코멘트 준수, 사실 표시 엄격, 검증 질문 명확, 핵심 메시지 한 줄 | — |

결론: DeckPick은 근거를 정직하게 다루지만 "판단을 미루는 보고서"에 머문다. "답을 먼저 주는 보고서"가 되도록 바꾼다.

## 2. 실행 대상: 1·2·6번 (프롬프트·검토 규칙만 바꿈, 유료 실행 없음)

### 1번. 결론 먼저 스토리라인
- 위치: `web/src/lib/storyline.ts`의 스토리라인 지시문.
- 변경: 표지 다음 장(2장)을 '결론 요약'으로 고정한다. 우선순위나 권고안과 각각의 한 줄 근거를 제시하고, 나머지 장은 그 결론을 뒷받침하는 순서로 배치한다.
- 검사: 스토리라인 결과 2장의 역할이 요약·판단인지 확인하고, 아니면 수정 요청한다. 오프라인 테스트를 추가한다.

### 2번. 유보형 핵심 메시지 상한
- 위치: `web/src/lib/deck-review.ts`(assessDeck / reviewAndRepairDeck).
- 변경: "판단할 수 없다 / 확인되지 않았다 / 추가 확인이 필요하다"류 핵심 메시지를 덱당 최대 2장까지 허용한다. 초과한 장은 "잠정 판단 + [가설] 표시 + 검증 조건" 형태로 고쳐 쓰도록 수정 지시를 만든다.
- 근거가 정말 없는 장은 유보를 유지하되 상한 계산에 넣는다. 사실 검증 규칙은 완화하지 않는다.
- 검사: 유보 문구 탐지 함수 단위 테스트, 상한 초과 덱 fixture 테스트.

### 6번. 레이아웃 최소 데이터·등급 의미
- 위치: `web/src/lib/expanded-layouts.ts`.
- survey-findings: `sampleSize`를 `positive()` → 최소 10으로 올린다(표본 n=1 오용 방지). n<30이면 장표에 '소표본' 표시를 강제한다.
- evaluation-matrix: 등급의 의미를 '사업 매력도/적합도'로 고정한다. 레이아웃 설명(use/minimum)과 생성 지시에 "근거 확인 정도를 등급으로 쓰지 말 것"을 추가한다. 근거 강도는 별도 표시로 둔다.
- 검사: 기존 49개 출력 보존 검사와 레이아웃 fixture 해시를 유지한다. 의도적으로 바꾼 장만 갱신한다.

### 공통 완료 기준
- `npm run typecheck`, `npm test` 통과(현재 177개 기준, 새 테스트 추가), `npm run build` 통과.
- 진행 문서 `docs/DeckPick-3차-안정화-진행.md`에 바꾼 파일·이유·결과·남은 일을 기록한다.
- 유료 확인 실행은 별도 예산 보고 후 사용자 승인 시에만 한다.
