# DeckPick 구현 확인 기록

검증일: 2026-10-28. 작업 범위는 앱 구현·사용자 참고 자료 분석·Vercel 프로젝트 연결이다. 배포는 사용자 지시로 진행하지 않았다.

## 실행 환경

- Node.js 24.20.0, npm 11.19.0 확인. 별도 재설치 불필요.
- 앱: `web/`, Next.js 16.4.3 App Router, React 19, TypeScript, zod 4, Tailwind 4, pptxgenjs 4.
- 기본 로컬 주소: http://localhost:3100 . 명세의 Next.js 14+ 조건을 충족한다.
- 참고 자료 299장 모두 텍스트 추출·로컬 렌더링·전체 축소본 검토. 상세 규칙은 `컨설팅스타일분석.md`.

## 실제 확인한 사항

- `npm.cmd run typecheck`: 성공.
- `npm.cmd run build`: 성공. `/`, `/new`, `/deck/[id]/[stage]`, `/api/[...action]` 생성.
- `npm.cmd test`: 9개 통과. 색상과 대비, 14종 스키마와 캔버스 경계, 잘못된 표·가짜 출처·중복 후보 거부, 제공자 요청 헤더, OpenAI 재검증, Claude Tool Use, Claude 5.5 JSON, 재시도 제한, 편집 중 저장 복구, PPTX 텍스트·도형·출처 노트 검증.
- `/api/key-check`에 키 없이 요청: 연결 안내 오류. 가짜 연결 성공을 반환하지 않는다.
- 브라우저: 대화 제안 → 명시적 반영 → 아웃라인 → 6장 후보 선택 → 문구 수정 → navy 변경 → 새로고침 → 저장 복구 → forest 복원 → 완료 → PPTX 실제 다운로드 확인.
- 재생성: 선택하지 않은 B 후보만 재생성하면 기존 A 선택을 유지한다. 현재 장 전체를 재생성하면 그 장의 선택이 해제되고 완성 버튼이 비활성화된다. 다시 선택하면 활성화된다.
- 직접 수정 중 필수 문자열을 비우면 미리보기는 안내를 표시하며 앱이 중단되지 않는다. 저장은 임시 상태를 보존하고, PPTX 출력은 유효성을 다시 검사한다.
- 모바일 390 × 844 설정에서 실제 문서 너비 375px, 가로 scrollWidth 375px 확인. 후보는 세로 배치, 채팅은 하단 배치. 임시 viewport는 검사 후 기본값으로 복원했다.
- PowerPoint로 14종 출력 파일을 열어 각 슬라이드를 JPG로 내보내고 전체 모음을 육안 검토했다. 화면 미리보기의 표지·박스·흐름·수직 구조·결론과 구조 및 색상을 대조했다. 모든 경우의 글자 간격이 픽셀 단위로 같다는 뜻은 아니다.
- Vercel 로그인 계정과 scope 확인 후 `deckpick` 프로젝트 연결. 마지막 배포 목록 확인: 없음. 토큰·키 값은 기록에 복사하지 않았다.

## 미검증·제한

1. 실제 OpenAI·Claude 키가 없으므로 제공자의 현재 계정 권한·결제 상태·실제 반환 형식·검색 결과와 내용의 품질은 미검증이다. 테스트는 공식 문서에 맞춘 대체 HTTP 응답으로 실시했다. API 연결 완료라고 보고하지 않는다.
2. 아웃라인의 추가·삭제·순서 조정, 명시적 제안 반영, 편집 초기화 확인은 구현했다. 세부 조합 전체를 브라우저로 반복 검증한 것은 아니다.
3. 실측 텍스트 크기는 PowerPoint와 브라우저가 다를 수 있다. 공유 줄바꿈·좌표와 최대 2pt 축소·넘침 경고를 적용했지만, 긴 실제 생성 문구는 최종 검토가 필요하다.
4. 미리보기 14종을 모은 로컬 QA HTML도 만들었다. 인앱 브라우저가 file 프로토콜 열기를 거부해 이 파일의 브라우저 검토는 하지 않았다. 이를 우회해 열지 않았다. 실제 앱에서 사용하는 대표 미리보기와 PowerPoint 출력은 별도로 확인했다.
5. 데모는 준비된 예시다. 실제 자연어 지시대로 내용을 바꾸는 기능은 실제 AI 모드에 있다.
6. 출처는 제공자 검색 결과에 포함된 URL만 허용하지만, 모든 주장의 사실 여부를 자동으로 검증하는 기능은 아니다. 검색 요약과 출처를 검토해야 한다.
7. 서버 API 키를 설정해 공개 서비스로 운영할 경우 인증·사용량 제한이 추가로 필요하다. 현재는 로컬 앱이며 배포되지 않았다.

## 가정

- 장 수는 5~12장 선택으로 노출했다.
- 브라우저에 마지막 덱 1개를 저장한다. 새 덱을 만들면 기존 덱을 대체한다는 확인을 거친다.
- 목차는 3~5개 섹션으로 묶고 다른 구조의 후보에서도 같은 목차 의미를 유지하도록 프롬프트에 지시했다.
- 기본 데모는 외부 출처가 없는 예시다. 제공 자료의 회사 수치·본문·브랜드 이미지를 예시 데이터로 재사용하지 않았다.
- 최신 Claude 모델과 명세의 강제 Tool Use 방식이 맞지 않아, 5세대는 공식 native JSON schema 방식으로 분기했다. 기존 모델 Tool Use 어댑터와 검증도 유지한다.
- 원본은 사용자의 기존 위치에 유지했다. 분석·검증 산출물은 현재 프로젝트 안에만 저장했다. Vercel 연결 루트는 `web/`이며 참고 원본·분석 텍스트는 포함하지 않는다.
