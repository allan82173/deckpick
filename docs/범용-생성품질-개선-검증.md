# DeckPick 범용 생성 품질 개선과 검증

검토일 2026-11-06. 사용자 제공 Claude 수정안을 앱 코드와 생성 지침에 반영했다. 특정 과제·업종·지역의 정답을 넣지 않았다. 기존 키와 선택 모델 `gpt-6-luna`를 재사용했으며, 다른 모델로 분업하지 않았다. 로컬 코드 작업이고 공개 배포는 하지 않았다.

## 작업 전 확인과 계획

변경 전 `research-pipeline.ts`, `ai.ts`, 역할별 후보 계획, 공통 장면·PPTX 출력, `slide-quality.ts`, API 경로와 편집 화면을 읽고 요약을 보고했다. 기존 흐름은 제목 중심 검색→근거표→목차→코드가 정한 레이아웃에 채우기→형식 검사였다. 공개 검색어 분류와 계산 보완에 특정 주거 과제의 규칙이 남아 있었고, 과제 해석·판단의 반전 조건·원문 문구 대조·전체 논리 검토가 분리되어 있지 않았다.

계획은 과제 해석을 공통 기준으로 저장하고, 질문별 공개 조사와 근거 부족 확인을 거쳐 판단·주장 지도·장표를 만든 뒤 전체를 검토하는 것이었다. 실제 원문·비밀키·배포 설정을 삭제하지 않았다. 변경 전 라이브러리는 `web/output/general-quality/baseline/src/lib/`에 보존했다.

## 범용 회귀 비교

`tests/fixtures/general-decks.json`의 서로 다른 5개 합성 과제를 사용했다. 모두 7장이고 색·목적도 다르다. 실제 사용자 자료나 특정 과제의 정답은 fixture에 넣지 않았다. 변경 전은 보존한 라이브러리로, 변경 후는 개선한 라이브러리로 실행했다. 같은 입력·같은 선택 모델을 썼다. 검색 시점과 모델 출력의 확률성 때문에 완전히 통제된 실험은 아니며, 각 입력을 여러 번 반복한 평균도 아니다.

성공은 요청한 장 수의 파일이 생성됐다는 뜻이다. 모든 내용·디자인 검사를 통과했다는 뜻이 아니다. 변경 전 실패는 세 경우 모두 기록으로 남겼고 품질 점수를 임의로 0점으로 채우지 않았다.

맥락 직접 근거는 핵심 판단의 지역·시장·대상을 직접 뒷받침하는 공개 근거를 엄격하게 센 값이다. 유용한 일반 지침·전국 시장 배경이 있어도 해당 조직의 문제나 특정 지역의 고객군을 직접 입증하지 않으면 제외했다. 원문 문구 대조는 문구의 존재 확인이며 주장 전체의 정확성 보증이 아니다. 변경 전의 0건은 대조 기록이 없다는 뜻이며 그 자료가 모두 틀렸다는 뜻이 아니다. 판단 비율과 공통 요구 위반은 같은 모델의 별도 공통 평가 결과다. 사실의 최종 판정이나 사람의 평가를 대체하지 않는다.

### 실제 결과를 보고 마지막에 추가한 검증

- 과제명·지역·업종이 아니라 일반적인 실패 원인을 고쳤다. 표지/마지막 장의 다른 이름 때문에 전체 구성을 버리지 않도록 정규화했고, 호출마다 허용한 레이아웃 ID만 응답 형식에 넣었다.
- 계획형 제목 하나 때문에 전체 스토리라인을 계속 재생성하지 않도록 그 제목만 별도 수정하는 같은 모델 호출을 연결했다.
- 원문 인용은 연속된 문구로 대조한다. 서로 떨어진 수치를 `81% vs. 75%`로 이어 붙인 표현을 원문 인용으로 통과시키지 않으며, 문구가 맞지 않으면 근거표 추출 단계에서 수정하거나 빈 값으로 남기게 했다. 확인할 수 없는 발행일은 비운다.
- 업무 개선 출력에서 `0.1%`와 `10%`의 표기 혼용을 발견했다. 현재 계산기는 % 입력을 일반 수량·시간과 곱하기 전에 100으로 나누도록 검사한다. 소수 승수 0.1은 단위 `비율`을 써야 한다. 계산 장에는 가정 변수와 산식 명세가 반드시 있어야 한다.
- 이 마지막 계산·인용 보강 뒤 위 5개 덱을 모두 유료로 재생성하지는 않았다. 따라서 위 표는 생성 실험에서 관측한 결과를 그대로 남긴 것이다. 보존된 업무 개선 계산을 최신 계산기로 다시 검사하면 거절되며, 시장 진입·제품 피치 계산은 통과한다. `calculation-audit.json`에 기록했다. 과거 저장 덱의 수치를 임의로 변경하지 않았다.

## 검증 산출물

- 자동 검사 96개 통과. 기존 후보 교체·첨부/사진·편집 보존·PPTX 검사와 새 개인정보 제거·근거 부족 게이트·산식·전체 검토·검토 상태 무효화 검사를 포함한다.
- TypeScript 검사와 프로덕션 빌드 통과. 로그는 `web/output/general-quality/typecheck.log`, `unit-test.log`, `build.log`다.
- 생성한 35장과 분석 레이아웃 예시 14장을 이미지로 렌더링해 모음 이미지를 확인했다. 글자 길이 경고가 남은 장은 위 표와 각 `inspection.json`에 기록했으며 시각 품질 전체 통과로 처리하지 않았다.
- 생성 PPTX 5개는 모두 7장·7개 노트이고 실제 텍스트의 서체는 Pretendard다. 편집 가능한 도형 수는 시장 진입 315, 업무 개선 277, 학술 요약 291, 제품 피치 252, 정책 316개다. 구조 검사는 `export-inspection.json`에 있다.
- 후보 비교 실제 호출에서 `c-comparison-table` / `c-positioning` / `c-argument-board` 세 구성이 반환됐다. 선택한 원본 장을 덮어쓰지 않고 `candidate-triplet.json`에 저장했다.
- 브라우저에서 생성 결과 HTML의 과제 해석·판단·요구사항과 원문 미확인 안내가 표시되는 것을 확인했다. 화면은 `browser-qa.png`다. 모바일 전용 브라우저 조작과 실제 PowerPoint 앱에서의 모든 개체 조작은 이번에 추가로 수행하지 않았다.

## 재실행과 적용 범위

앱은 새로고침한 뒤 새 초안을 생성하면 새 파이프라인을 사용한다. 기존 저장 덱은 자동으로 다시 만들지 않는다. 원문 근거가 부족하면 화면에서 자료를 보완하거나 한계를 표시하고 진행을 선택한다. 완성 초안에서 전체 논리 검토를 다시 실행할 수 있다. 공개 사이트의 실제 AI 기능·키·배포 제한은 변경하지 않았다.

명령은 `2번 최종프로젝트/web/`에서 실행한다.

```text
npm run test
npm run typecheck
npm run build
node --env-file=.env.local --import tsx tests/run-general-benchmark.tsx --before
node --env-file=.env.local --import tsx tests/run-general-benchmark.tsx
node --env-file=.env.local --import tsx tests/evaluate-general-benchmark.ts
node --import tsx tests/render-general-benchmark.tsx --layouts
node --import tsx tests/audit-general-calculations.ts
```

생성 실험은 기존 저장 결과와 중간 조사 기록이 있으면 이어서 수행한다. 새 독립 실행과 반복 통계가 필요하면 기존 결과를 보존한 별도의 실행 폴더를 사용해야 한다. 실제 API 실험은 크레딧을 사용하며, 다단계 조사·검토 때문에 호출 수와 대기 시간이 늘었다. 정확한 총 결제액은 이번에 측정하지 않았다.

주요 결과 위치는 `web/output/general-quality/metrics.json`과 `before/`, `after/`의 각 과제 폴더다. 각 폴더의 `deck.json`, `evaluation.json`, `preview.html`, `montage.jpg`, `generated.pptx`로 결과를 확인할 수 있다. 실패 메시지는 이전 실패 기록으로 보존했다. 최종 완료 여부는 파일 하나의 유무가 아니라 덱·검토·검증 표를 함께 확인한다.

장표 이미지·글자 넘침·서체·형식 반복을 확인했다. 생성·빌드는 통과했으며, 위에 적은 내용·표기·원문 대조·길이 경고는 미해결로 남겼다.
