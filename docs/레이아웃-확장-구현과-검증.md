# DeckPick 레이아웃 확장과 비공개 코드 공유

확인일: 2026-11-07. 새 23개 배치 유형을 코드에 구현했다. 모델 파인튜닝을 수행한 것은 아니다. 사용자 원본 PPTX는 읽기만 했으며 삭제하지 않았다.

## 결과와 수량

- 과거 HTML의 26개 표기는 최신 코드와 달랐다. 기존 코드는 컨설팅·마케팅 중복을 제외한 33개 배치, 49개 구현 ID였다.
- 새 23개 배치를 두 덱 유형에 공용 등록해 **56개 배치 / 95개 구현 ID**가 됐다.
- 앱 상단 ‘디자인 유형’ → `/catalog`, `web/output/deckpick-design-catalog.html`에서 실제 예시를 확인한다.
- 색상·디자인 시스템 선택 기능은 유지했다.

## 단계별 변경과 검증

| 단계 | 추가 유형 | 서로 다른 예시 | PPTX 원본 차트 / 내장 XLSX | 결과 |
|---|---:|---:|---:|---|
| 1 판단·근거 | 7 | 14장 | 2 / 2 | 스키마·좌표·웹 텍스트 경고 검사 통과 |
| 2 차트·계산 | 6 | 12장 | 10 / 10 | 워터폴 복구 오류와 도넛 중심 표시 수정 후 PowerPoint 열기 통과 |
| 3 일정·시간 | 3 | 6장 | 0 / 0 | 실제 날짜 및 기간 계산 검사 통과 |
| 4 구성 보완 | 7 | 14장 | 0 / 0 | 이미지 필수 조건·가상 페르소나 구분 검사 통과 |

모든 46장 예시를 웹 이미지와 실제 PowerPoint PDF로 출력했다. `web/output/layout-expansion/stage-N/`에 PPTX·PDF·검사 JSON이 있고 `native-render/`에 PDF의 페이지 이미지와 모음 이미지가 있다. 차트 단계 최신 PDF는 `stage-2/stage-2-final.pdf`다. 이전 `stage-2.pdf`는 도넛 위치 수정 전 진단본이다.

자동 검사 108개 통과, 형식 검사와 제품 빌드 통과. 마지막 도넛 수정 후 관련 12개 검사도 다시 통과했다. 기존 49개 장면의 해시와 PPTX 슬라이드 XML을 수정 전과 비교해 모두 일치했다. 단일 레인 고객 여정도 선택 확장이 없으면 기존 장면을 그대로 사용한다.

### 실제 PowerPoint에서 발견하고 수정한 문제

- 누적 막대 기반 워터폴에서 데이터 레이블 위치 `outEnd`가 PowerPoint 복구를 유발했다. `ctr`로 바꾸고 회귀 검사를 추가했다. 수정본은 복구 알림 없이 열린다.
- 도넛의 중심 숫자가 자동 범례 때문에 왼쪽으로 벗어났다. 차트 영역과 편집 가능한 별도 범례를 배치해 중심을 맞췄다. 최신 PDF의 실제 렌더를 확인했다.
- 차트 우클릭 → 데이터 편집에서 내장 데이터 표가 열리는 것을 직접 확인했다. 증거: `web/output/layout-expansion/native-chart-edit-data.png`. 모든 차트 계열의 개별 값 수정·재계산까지 수동 반복한 것은 아니다.

### 남은 시각 검증 문제

- PPTX XML에는 Pretendard가 지정돼 있고 로컬 폰트 파일도 있으나, 이 PC의 PowerPoint PDF는 Calibri·맑은 고딕으로 대체한 결과를 출력했다. PowerPoint 재시작 뒤에도 동일했다. **Pretendard 대체 없음 검증은 미통과**이며 완전한 서체 재현을 완료했다고 주장하지 않는다. 기존 49개 출력 불변 조건을 지키기 위해 전체 내보내기 서식을 바꾸지 않았다.
- `comparisons/`의 23개 비교 이미지는 왼쪽이 원본 XML 좌표로 만든 구조도, 오른쪽이 웹 렌더다. 원본 49장 PPTX를 PowerPoint PDF로 변환해 같은 번호와 나란히 비교하는 검증은 아직 남았다. 구조도를 원본의 실제 렌더라고 해석하면 안 된다.
- 예시 두 종류에서 넘침 경고는 없지만 모든 최대 길이 조합의 실사용 편집까지 보증하지 않는다. 빈 데이터·행/열 초과·잘못된 날짜는 생성 실패로 처리한다.

## 바뀐 파일과 동작

- `web/src/lib/expanded-layouts.ts`: 데이터 스키마, 최소 데이터, 역할·사용·비사용 조건과 양쪽 덱 등록. 표본·조사 기간·이미지·날짜·배열 크기·등급을 검증한다.
- `web/src/lib/expanded-scene.ts`: 공통 태그·평가 기호·헤더·결론 바·연결 표시·마일스톤과 23개 동적 배치. 선택된 디자인 토큰을 사용한다.
- `web/src/lib/native-charts.ts`: 웹 차트와 pptxgenjs 원본 차트. 증감의 0선 교차를 처리하고 시각화의 입력 수치를 검증한다.
- `web/src/lib/model.ts`, `scene.ts`, `export.ts`, `demo.ts`: 스키마·미리보기·PPTX·합성 예시 연결.
- `web/src/lib/candidate-plan.ts`, `slide-quality.ts`, `storyline.ts`, `ai.ts`: 역할별 후보 목록과 최소 데이터 지침을 모델에 전달한다. 후보 3개가 서로 다른 형식을 쓰도록 계획한다. 실제 사진이 없으면 캡처 주석형을 억지 생성하지 않는다.
- `web/src/lib/attachments.ts`, `vision.ts`: 실제 이미지 ID와 크기를 전달한다. 임의 외부 URL을 이미지 근거로 받아들이지 않는다.
- `web/src/lib/layout-catalog.ts`, `web/src/app/catalog/page.tsx`, `studio.tsx`, `globals.css`: 최신 수량과 예시를 보여 주는 카탈로그 및 진입 버튼.
- `web/tests/layout-expansion.test.ts`, `tests/fixtures/legacy-layout-*.json`: 데이터·원본 차트·날짜 계산·기존 출력 보존 검사.

이번 작업에서는 유료 모델을 호출해 실제 과제 생성 품질을 재평가하지 않았다. 검사 통과는 사실 검증이나 Claude와 동등한 내용 품질을 뜻하지 않는다.
