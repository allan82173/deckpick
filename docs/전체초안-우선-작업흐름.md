# 전체 초안을 먼저 보는 작업 흐름 · 2026-10-29

## 사용자 피드백

배치 구조를 먼저 고르면 완성 결과를 판단하기 어렵다는 피드백을 반영했다. 사용자는 내용이 채워진 전체 덱을 먼저 보고, 마음에 들지 않는 장만 다른 후보로 바꾸기를 원했다. 기존 단계별 구조 선택보다 이 요청을 우선한다.

## 새 기본 흐름

자료·대화 → 내용과 구성을 채운 전체 초안 → 필요한 장만 다른 후보/문구 수정 → PPTX 다운로드.

- 입력 화면의 ‘전체 초안 만들기’는 목차를 만든 뒤 바로 전체 초안 화면으로 연결한다. 대화의 구성 제안을 반영할 때도 같은 화면으로 이동한다.
- 목차 조정 화면은 필요할 때 열 수 있는 보조 단계로 유지한다. 수동 조정 후 전체 초안을 만들 수도 있다.
- `pick` 경로의 기본 화면은 전체 덱이다. 장마다 선택된 결과 하나를 크게 보여 준다. 처음에 후보 3개나 도식 라이브러리를 고르도록 요구하지 않는다.
- 새 덱은 장마다 1개 후보만 생성해 자동 적용한다. 참고 자료의 표현 규칙과 내용 관계 기반 추천을 사용한다. 미확인 사실이나 숫자를 채워 완성된 것처럼 표현하지 않는다.
- ‘이 장 다른 후보 보기’를 누르면 현재 초안을 유지한 채 해당 장의 빈 후보 자리만 추가한다. 이미 3개 후보가 있으면 새 요청 없이 비교 화면을 연다. 기존 초안과 직접 수정한 내용은 추가 후보 생성 중에도 유지한다.
- AI 모드의 추가 후보 요청에는 현재 초안의 제목·본문·노트를 문맥으로 보내고, 같은 메시지·근거를 다른 구조로 표현하도록 지시한다. 첨부 입력량 제한과 사진 포함 옵션을 유지한다.
- 비교 화면에서 원하는 후보를 선택하고 전체 초안으로 돌아오면 결과가 반영된다. ‘전체 본문 유형 보기’는 이 장별 수정 화면의 선택 기능으로 유지한다.
- 전체 초안에서 문구 직접 수정과 다운로드가 가능하다. 빈 값 등 유효성 문제가 있으면 다운로드를 막는다.

## 비용·저장·오류

최초 요청은 목차 요청 뒤 장당 1개 초안을 순차 생성한다. 장마다 3개를 일괄 생성하던 방식보다 초기 후보 생성량을 줄인다. 다만 장당 요청의 검증 수정이나 이후 후보 요청에는 추가 사용량이 발생할 수 있으며 비용을 보장하는 수치로 표현하지 않는다.

기존 저장 덱에서는 사용자가 선택한 후보와 직접 수정한 내용을 우선한다. 선택만 없고 이미 후보가 있으면 첫 후보를 초기 초안으로 연결한다. 만들어진 장은 다시 생성하지 않는다. 직접 수정 중인 불완전한 값도 자동으로 덮어쓰지 않는다.

새 초안은 장별로 브라우저에 저장된다. 중간에 실패하면 완성된 장은 남고 ‘미완성 장 이어서 만들기’로 없는 장만 재개한다. 목차 또는 덱이 바뀌었거나 화면을 떠난 경우 이전 요청의 결과로 다른 초안을 덮어쓰지 않는다.

데모는 준비된 예시 문구이며 실제 사용자 자료를 분석한 결과가 아니다. 이 변경은 로컬 앱 구현이다. 실제 유료 API 생성 품질은 별도 검토가 필요하고 공개 배포는 수행하지 않는다.

## 검증

타입 검사·테스트 48개에서 최초 장별 1개 생성 결과의 자동 적용, 기존 선택·수정 보존, 추가 후보만 붙이는 동작, 불완전한 수정 보존, 목차 문맥 검사, 후보를 검토하기 전에도 전체 PPTX가 편집 가능한 텍스트·도형으로 출력되는지 확인했다. 샘플 산출물은 web/output/full-draft-workflow-validation.pptx다.

프로덕션 빌드가 통과했다. 별도 로컬 검증 주소의 새 데모에서 입력 → 전체 초안 6장 표시 → 3번 장의 대안 보기 → 후보 B 선택 → 전체 초안 복귀를 실행했다. DOM 비교로 3번 장만 바뀌고 나머지 5장은 그대로임을 확인했다. 브라우저에서 사진 포함 PPTX를 내려받아 6개 슬라이드와 임베디드 미디어를 확인했다. 실제 다운로드 파일은 web/output/full-draft-browser-validation.pptx이며, 화면은 web/output/screenshots/full-draft-first-workflow.png에 있다. 유료 API 호출은 수행하지 않았다.
