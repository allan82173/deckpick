# DeckPick 3차 개선 — 단계별 기록

기준일: 2026-11-07. 목표는 모델 품질 상향이 아니라 안정적인 종료·비용 절감·재현 가능한 측정이다. Luna, 키, 디자인 선택과 기존 후보·직접 편집·첨부·장별 대화·PPTX 기능을 유지한다. 파일은 삭제하지 않는다. 단계 완료 기준을 통과한 뒤 다음 단계로 진행한다. 4단계 유료 실험은 계획을 제시하고 사용자 승인 전에는 실행하지 않는다.

## 1단계 — 완료

### 수정한 파일과 동작

- `web/src/lib/research-questions.ts`, `research-pipeline.ts`: 공개 근거를 행별로 검사한다. 잘못된 URL·질문 ID와 구조 오류는 rejectedRows에 기록하고 제외한다. 인용 문구만 불일치하면 행을 유지하고 originalText를 비우며 원문 미확인으로 표시한다. 유효 행이 0개일 때만 한 번 더 추출하고, 여전히 0개면 gaps로 넘긴다.

- `web/src/lib/run-budget.ts`, `ai.ts`, `generation-config.ts`: 질문 4분, 스토리라인 4분, 장 후보 생성 3분, 검토 4분을 적용한다. 요청 1회는 최대 75초이며 연결·일시 오류에 1초/2초 지수 백오프를 적용해 최대 2회 재시도한다. 형식 재시도·출력 한도 재시도와 별도 예산이다. 단계의 전체 시간 제한이 우선한다.
- `web/src/lib/run-checkpoints.ts`, `storyline.ts`, `deck-review.ts`: 과제 해석·계획·첨부 청크·질문별 조사·근거표·판단·스토리라인·장 후보·검토 결과를 `.generation-runs/`에 저장한다. 같은 실행 ID와 입력은 완료한 결과를 재사용하며, 미완료 단계는 재사용하지 않는다. 공개 데모·다른 출처 요청은 저장 전에 차단한다.
- `web/src/app/api/[...action]/route.ts`, `run-attempt-report.ts`, `run-report.ts`: 성공과 실패 API 실행마다 별도 MD/JSON 리포트를 `output/run-reports/attempts/`에 남긴다. 실패 리포트를 뒤의 성공으로 덮어쓰지 않는다. rejectedRows·원문 확인 상태·이어 하기 상태를 포함하고 키·첨부 전문은 제외한다.
- `web/src/components/studio.tsx`, `store.tsx`, `full-draft-review.tsx`: 연결이 끊겨도 실패 상태와 완료 단계가 유지된다. ‘이어서 생성’ 및 ‘미완료 검토 다시 실행’을 제공한다. 검토 시간 초과는 완성 장을 보존하고 status=incomplete로 반환한다.

## 2단계 — 구현·오프라인 검증 완료 / 전체 생성 실측 미통과

### 수정한 파일과 동작

- `web/src/lib/evidence-selection.ts`: 장별 evidenceRefs만 선택한다. 판단·스토리라인·덱 검토에는 질문당 상위 8개 출처를 선택한다. 맥락 일치→원문 확인→자료 유형→발행일 순으로 정렬한다. 내부 첨부 근거와 확정 사항은 전체를 유지하되 중복을 합친다. 같은 URL의 서로 다른 주장은 relatedFacts로 보존하고, 이전 ID는 aliasIds로 연결한다. 공개 출처의 인용 전문은 재전달하지 않고 확인 상태와 주장을 보낸다.
- `web/src/lib/research-questions.ts`, `source-pages.ts`: 원문은 다운로드 한도 안에서 전체 텍스트로 보관해 인용 대조에 사용한다. 추출 호출에는 질문 핵심어가 있는 문단과 앞뒤 1문단만 페이지당 최대 5,000자 보낸다. 같은 검색어·URL은 실행 안에서 재사용하고, 같은 URL의 여러 주장을 서로 다른 출처 수로 세지 않는다.
- `web/src/lib/concurrency.ts`, `ai.ts`, `studio.tsx`: 질문 조사와 장 생성은 최대 3개 작업을 병렬 처리한다. 제공자 호출도 프로세스당 최대 3개로 제한한다. 실패한 장 외의 성공한 장은 저장한다.
- `web/src/lib/storyline.ts`, `deck-review.ts`, `ai.ts`: 선택한 근거를 실제 요청에 적용하고 장별 전달 전/후 행 수를 execution.evidenceScopes에 기록한다. 좌표·여백 경고는 표시하되 모델에게 문구를 다시 쓰게 하는 수정 루프에서 제외한다. 렌더러 수정 자체는 5단계에 남긴다.
- `web/src/components/evidence-review.tsx`, `run-report.ts`, `execution-model.ts`: 묶인 출처의 추가 주장과 미확인 상태를 화면과 리포트에 보존한다. 원문 전체와 비밀키는 리포트에 넣지 않는다.
- `web/scripts/prepare-github-share.cjs`: 비공개 체크포인트 폴더를 공유 제외·검사 대상에 추가했다. 이번 작업에서 GitHub 업로드·배포는 하지 않았다.

### 설정과 비용 절감의 구분

모델과 effort 기본값은 유지했다. 조사 최대 라운드는 질문당 2회, 검색 호출당 도구 사용은 1회, 결과 출처 8개, 라운드 요약 6,000자로 조절했다. 원문은 질문당 최대 3개·덱 전체 최대 12개, 단계 시간 제한과 재시도 예산은 1단계와 같다. 병렬 수 3, 상위 근거 8개/질문, 출처당 전달 주장 최대 3개, 문단 발췌 5,000자는 모두 generation-config.ts에 있다. 목표는 10분 이내·기존 C 입력 토큰의 1/3 이하다. 실제 달성 여부는 실측 결과로 판정한다.

### 오프라인 결과

자동 테스트 138개 통과, 타입 검사·프로덕션 빌드 통과. 검증 기록은 `web/output/quality-execution/tests-stage3-2-final.txt`, `build-stage3-2.txt`다. 새 테스트는 선택 범위와 우선순위, 같은 URL의 미확인 주장 보존, 60,000자를 넘는 원문의 후반 핵심어 발췌, 동시 처리 상한 3·부분 실패 보존, 실제 후보·장별 대화 요청 본문에서 무관한 공개 근거 제외를 확인한다. 시각 경고를 남기면서 그 경고만으로 추가 생성 호출을 하지 않는지도 검사했다. 이 결과만으로 속도·토큰 목표 달성을 주장하지 않는다.

### 최소 유료 실행 사전 예산

기존 market-entry 입력 1회. 예상 25~50회 호출, 입력 15만~45만 토큰, 6~10분(재시도 초과 가능)을 실행 전에 사용자에게 알렸다. 기존 C의 부족 근거를 기록한 채 계속하는 평가 정책과 같은 정책을 사용한다. 검색 결과는 고정하지 않았으므로 품질 또는 effort의 인과 효과를 해석하지 않는다. 실행 ID별 별도 리포트와 실패·미완료 상태를 보존한다. 큰 비교 실험은 실행하지 않았다.
